## Procfs, control, and lifetime review

The native `run_bwrap_with_proc_fallback` preflight can omit a fresh procfs mount while retaining bubblewrap's user, mount, and PID namespaces and the requested filesystem/network policy. The runner does not reject this inherited view. Host PIDs and policy-permitted metadata can be visible, and procfs PIDs need not match namespace PIDs. In the tested restricted-policy matrix, host environment, root/cwd/fd links, memory, signals, and control interfaces remain inaccessible; visibility is not host process authority. The [Linux compatibility comparison](LINUX_COMPATIBILITY.md) links the actual differential tests and their evidence limits. The local identity-interposer regression checks acceptance, not that entire security matrix.

Procfs is still used: the outer runner enumerates `/proc/self/fd` for descriptor hygiene, Linux private-storage cleanup uses descriptor paths there, and native helper setup and verified descriptor execution use procfs paths. Neither removal of host process discovery nor support for inherited procfs establishes procfs-free operation. Supervised Linux execution still rejects full-disk-write policies. Explicit Landlock has its own policy/capability checks and no supervised lifetime; it is never an automatic response to namespace failure.

Linux readiness obtains namespace init's host identity from kernel socket credentials. An optional pidfd allows SIGKILL even when init is stopped. If pidfd opening or signalling returns `ENOSYS`, `EPERM`, or `EACCES`, ordinary retirement shuts down the host channel's write direction; init sees EOF and exits. The supervisor must still obtain its known native child's completion status. Missing status, termination errors, or a stopped/uninterruptible init exceeding the deadline produce failure and retained storage, not successful cleanup.

The restricted-network filter in [linux-sandbox/src/landlock.rs](../linux-sandbox/src/landlock.rs) is unchanged from upstream. Native init uses descriptor `read`/`write`, which remain allowed, rather than socket operations denied by that filter. `restricted_network_preserves_native_socket_denials_and_descriptor_io` protects this boundary. The host configures credentials before launch; its unrestricted setup writes are distinct from the filtered native endpoint. The control descriptor persists in namespace init after setup and is excluded from the workload.

Configured caller death leaves a living runner to retire processes and then delete private storage. Runner death removes that cleanup owner. Linux's parent-death links can terminate the native chain after readiness, but do not delete storage or provide independent recovery. Review the direct child's creating thread, namespace-init re-arming after credential/exec transitions, and native TERM links in [proxy_lifecycle.rs](../linux-sandbox/src/proxy_lifecycle.rs), synthetic-mount supervision, and [vendored bubblewrap](../vendor/bubblewrap/bubblewrap.c). Preserve the startup windows and supervisor-loss limits in [LIFECYCLE.md](LIFECYCLE.md#owned-stdio-process-groups-and-linux-parent-death); those limits also apply when tests pass.

The independent Linux observers in [ownership_tests.rs](tests/lifecycle/ownership_tests.rs) use pidfds, host child lists, and `NSpid` to verify exits and clean up failed fixtures. These are test-host requirements, not runner requirements. Fault interposers depend on actual syscall and helper boundaries; review those checkpoints on upgrades without substituting sleeps, retries, or documentation snapshots.

## Configuration and build boundaries

Both transports accept owned, immutable configuration under [PROTOCOL.md](PROTOCOL.md). Environment input is copied by the OS at exec and cannot be changed by subsequent parent-environment edits, even before parsing. Framed-descriptor input becomes fixed only after the complete request is accepted; the trusted caller must control its bytes and writers until then. Closing/removing transport resources prevents propagation, not authentication or secure erasure. Target overrides reach only the enforced target boundary, and native proxy endpoint translations take precedence.

The upstream shared policy models, proxy implementation, Seatbelt policy files, seccomp rules, vendored bubblewrap, and helper build recipe remain unchanged. The added manifest/workflow select the release's musl linkage: build and strip the helper, embed its digest, then build the runner with vendored OpenSSL. Keep build variables scoped to these builds and GNU interposer tests separate from static artifact tests. [README.md](README.md#build-and-validation) describes packaging; [REBASE.md](REBASE.md) owns the upgrade checks.
