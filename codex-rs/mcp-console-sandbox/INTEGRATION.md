## Self-contained additions

The runner owns configuration, signal capture/restoration, lifecycle sequencing, native gate payloads, temporary storage, and platform kernel operations in its own `src/` files. `launch.rs` shares sequencing; `platform_macos.rs` and `platform_linux.rs` contain only the operations that differ. Tests, fixtures, the protocol, and [behavior mapping](LIFECYCLE.md#executable-acceptance-tests) stay in this package.

`src/codex.rs` is the only integration module. It translates the owned request into the pinned native filesystem policy, `PermissionProfile`, `SandboxManager` transformation, structured Seatbelt profile, and `RemoteNetworkProxyConfig`/`NetworkProxy` lifetime. Configuration exposes the existing upstream filesystem/network/proxy wire types; these remain internal-version dependencies despite the executable boundary. No lifecycle code imports upstream orchestration types. The native setup payload is private to one launch, not a second public protocol or an abstraction framework.

The upstream seccomp deny rules, proxy implementation, vendored helper, shared protocol model, and MCP Console files remain unchanged. Optional private-storage permissions and caller-supplied Seatbelt extensions are composed in the runner. Workspace registration and Cargo lock changes are listed in [REBASE.md](REBASE.md#existing-upstream-files).

Native helper dispatch retains the earlier extraction's documented leading-option convention. It is an upgrade review point, not an inferred process-layout contract. Linux readiness obtains the native init's host identity from socket credentials and pins it with a pidfd; it does not search for a particular helper tree.

The gated native endpoint uses `File` read/write on its owned socket descriptor. This avoids the `sendto` syscall used by Linux `UnixStream::write` while retaining kernel-supplied readiness credentials. `SO_PASSCRED` is configured by the host supervisor before native launch. The executable regression `restricted_network_preserves_native_socket_denials_and_descriptor_io` checks all six restored socket-operation denials and successful descriptor I/O on Linux, while retaining macOS behavior. Startup cancellation and caller-death tests exercise the credential-dependent gate with the upstream filter active. Review these assumptions when upgrading Rust or the native filter.

Darwin's libproc/kqueue observation boundary, `sandbox_init_with_parameters`, and Linux's subreaper/pidfd/procfs APIs are platform dependencies. Fault-injection fixtures interpose actual host syscalls to establish causal startup/watch checkpoints and verify failure reporting. They add no production test hooks. Acceptance tests also check that target-side loader constructors run only after enforcement. Do not replace those checks with sleeps or implementation snapshots during rebasing.

## Validation of this continuation

Local native validation uses macOS arm64 and the existing Ubuntu 24.04 x86_64 checkout on `mule`, kernel 6.8.0-139, with the pinned Rust 1.95.0 toolchain. Linux's AppArmor setting blocks the locally built bubblewrap's network namespace initialization unless its execution uses the host's existing `bwrap` profile. The executable tests use a task-local compiled launcher that immediately execs `aa-exec -p bwrap -- <ordinary-built-bwrap>`; no host security setting or repository helper implementation is changed. Native Linux tests use the installed host bubblewrap directly. This host accommodation is not a shipped executable dependency.

The debug and release executable suites passed 54 tests on macOS and 52 on Linux, with retries disabled. The native suites passed 92 tests on macOS with the two established exclusions, and all 207 tests on Linux. The macOS Bazel executable suite passed. Scoped Clippy, `just fix`, argument-comment lint on macOS, `just fmt`, and `git diff --check` passed. `just bazel-lock-update` completed without lockfile changes; the leaf explicitly selects Tokio's runtime, timer, and macro features without changing dependency versions.

The Linux Bazel build passed, but its full executable test run is limited by this host's AppArmor policy: the actual bundled helper fails network namespace setup with `loopback: Failed RTM_NEWADDR: Operation not permitted`. Replacing that verified helper with the Cargo test launcher correctly fails the native digest check. Neither verification nor host security settings were weakened to obtain a green result. The Cargo debug/release suites exercise the same Linux supervisor and native Rust hook using the ordinary helper through the existing AppArmor profile. A namespace-enabled CI host is still needed for the unmodified Linux Bazel runtime gate. The focused hosted workflow has not been run as part of this local task.

## Validation after restoring upstream socket rules

The executable regression first failed because all six socket operations succeeded under the relaxed policy. Restoring upstream `landlock.rs` then exposed `native target setup: Operation not permitted` before target execution. Changing the native endpoint to descriptor read/write made the regression pass, including successful local socket-pair I/O and all six expected `EPERM` results on Linux.

The complete debug and release executable suites passed 52 tests each on Linux and 54 each on macOS, with retries disabled. All 207 Linux native tests and the macOS Bazel executable suite passed. The macOS debug run reported five Nextest output-descriptor `LEAK` annotations despite passing assertions; the release run had none. Their cause was not isolated by this change. Linux Cargo tests used the same test-local AppArmor launcher described above. The Linux Bazel runtime gate was not repeated; its documented host restriction remains a validation limitation.

Scoped `just fix` passed on both platforms; the macOS argument-comment lint and `just fmt` on both platforms passed. Native `landlock.rs` is byte-for-byte identical to release commit `90854393966b21e9ebfd21b122334eb09a20c93d`. No dependency or lockfile changes were needed.
