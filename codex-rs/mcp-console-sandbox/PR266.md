# Historical runner fixes for MCP Console PR #266

This validation record applies to the revisions below, not the current branch. In particular, its Linux procfs refusal and adopted-descendant tracking were superseded by `7aacbcf1bca0f173f036617a5ee8ae71e18fb8cc`. Current behavior and upgrade guidance are in [LIFECYCLE.md](LIFECYCLE.md), [INTEGRATION.md](INTEGRATION.md), and [REBASE.md](REBASE.md). Preserve the results and limitations here as historical evidence, not requirements to reintroduce removed mechanisms.

Implementation commit: `fe1b9e4e89458ba8812bfb0a65fb0a1ad84e71d5`. The executable contract remains `mcp-console-sandbox --config-env NAME -- COMMAND [ARG]...`, with ordinary argv, cwd, environment and standard streams. The selected variable contains policy and lifecycle JSON and is excluded from helper and target environments. The existing framed-descriptor mode remains available. No configuration interface, request-size limit, proxy requirement, or socket allowance was added.

## Fixes and executable regressions

| Change                                                             | Root cause and result                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Regression                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Preserve root identity and retire the owned group                  | `Child::try_wait` reaped the native root before retirement. Darwin tracked observed descendants but did not enumerate the original group, so a child orphaned before discovery could survive a successful exit and storage removal. `waitid(WNOWAIT)` now preserves the root identity until retirement finishes. Darwin repeatedly enumerates live members of that pinned group and retires them alongside observed detached identities. Linux also leaves the direct root unreaped while retiring adopted descendants. | `retirement::root_exit_retires_unobserved_group_and_closes_partial_output` pauses Darwin discovery before the fork and resumes only after root exit; covers statuses 0 and 23, held standard streams, an incomplete output frame, and survival of an unrelated host process.                                                                                                              |
| Observe cancellation after readiness                               | A readiness receive and target-release write happened in the same supervisor iteration. Cancellation arriving during readiness could therefore release the target. Readiness now returns to the supervisor's cancellation check before any setup payload is sent.                                                                                                                                                                                                                                                       | `cancellation::cancellation_at_native_readiness_prevents_target_release` injects cancellation at the successful receive and checks the target-execution marker.                                                                                                                                                                                                                           |
| Retire partial setup before closing its channel                    | The setup channel was scoped inside the startup future. Returning for cancellation closed it before retirement, waking the native reader with an EOF error. The supervisor now retains it through retirement. Darwin stop/continue wait notifications are consumed without reaping or misclassifying the root.                                                                                                                                                                                                          | `cancellation::cancellation_during_partial_setup_retires_reader_before_closing_gate` and `cancellation::cancellation_retires_a_stopped_partial_setup_reader` check bounded stream closure, target nonexecution, storage removal and stderr. Each startup regression runs SIGTERM retirement and configured caller death.                                                                  |
| Refuse unsuitable Linux procfs without panic (historical behavior) | The native hook's procfs identity check and setup errors used panic paths. This revision changed expected failures to a nonzero startup diagnostic. The later Linux compatibility change removed the refusal.                                                                                                                                                                                                                                                                                                           | `prerequisite::unsuitable_inherited_procfs_is_rejected_without_panic_or_target_execution` in the [test file at fe1b9e4e8](https://github.com/t-kalinowski/codex/blob/fe1b9e4e89458ba8812bfb0a65fb0a1ad84e71d5/codex-rs/mcp-console-sandbox/tests/lifecycle/prerequisite_tests.rs) injected a mismatched `/proc/self` identity with `RUST_BACKTRACE=1`. It is not a current test selector. |

The generic partial-output fixture retains an unfinished frame on stdout; it has no Console sideband or worker dependency. The runner owns process retirement, not frame parsing or application draining. Existing executable coverage still exercises detached descendants, cancellation before native readiness, incomplete bootstrap, caller death, stdin/EOF, binary data, inherited signals, terminal handling, filesystem/network enforcement, descriptor isolation and same-user attempts to control the supervisor. See the complete [behavior mapping](LIFECYCLE.md#executable-acceptance-tests).

The startup red runs used `6f60c41139fb516a338184ca2585ecdd04a78906`, before the cancellation fix `f46ff2a165b8807e7a3de29ca640942145293057`. The two macOS native failures are `seatbelt::tests::create_seatbelt_args_with_read_only_git_pointer_file` and `seatbelt::tests::create_seatbelt_args_with_read_only_git_and_codex_subpaths`. No native expectation was edited. The final macOS debug LEAK annotation was in `configuration::configuration_is_explicit_json_without_file_fallback`; the release annotation was in `filesystem_policy_denies_and_grants_writes`. Assertions passed, but the annotations were not isolated or claimed fixed. An earlier intermediate macOS run also reported annotations in two older tests.

Mule's existing AppArmor policy requires the previously documented test-only `aa-exec -p bwrap` launcher to execute the ordinary built helper. No host policy, kernel setting or helper enforcement was changed. That profile rejects nested namespace creation before the real inherited-procfs reproduction reaches the runner. The syscall-injection regression passes; the full nested-namespace reproduction remains unvalidated on this host. Linux Bazel runtime, hosted CI, and Console integration/installation suites were not run for these fixes. Runner validation alone does not establish that PR #266 is ready to merge.

Scoped Clippy fixes and `just fmt` completed on both hosts after tests. Clippy removed a redundant `PathBuf` allocation in the procfs comparison. The macOS argument-comment lint passed on the final formatted tree. Tests were not rerun after those steps. Unrelated remote justfile formatter changes were discarded after inspection.
