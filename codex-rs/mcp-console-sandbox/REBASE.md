# Reapplying the native sandbox extraction

[INTEGRATION.md](INTEGRATION.md) is the authoritative current inventory: every changed path outside the runner, the added native control module, runner modules, upstream assumptions, and protecting behavioral tests. Use that inventory and the source when moving to another release.

## Procedure

1. Fetch the latest extraction branch and record its exact tip. The current base is `rust-v0.150.1`, commit `90854393966b21e9ebfd21b122334eb09a20c93d`. Inspect the complete base-to-tip diff, including subsequent compatibility and artifact work:

   ```sh
   git fetch origin mcp-console/sandbox-runner/rust-v0.150.1
   sandbox_tip=$(git rev-parse origin/mcp-console/sandbox-runner/rust-v0.150.1)
   git diff --name-status 90854393966b21e9ebfd21b122334eb09a20c93d "$sandbox_tip"
   git diff 90854393966b21e9ebfd21b122334eb09a20c93d "$sandbox_tip"
   ```

2. Start a new branch/worktree at the next exact upstream release. Keep the existing extraction branch and its history intact. Reapply the current net change against the new interfaces in small commits. Historical commits include removed policies, requirements, and process layers; replaying the entire history is not the specification. Keep native integration edits, the runner/tests, and build registration/artifacts reviewable separately.
3. Review every integration row against the new source and its callers. Preserve the [protocol](PROTOCOL.md), [capabilities](CAPABILITIES.md), and [lifetime boundaries](LIFECYCLE.md), including inherited procfs, optional pidfds, configured caller death versus runner loss, and incomplete-retirement reporting. Do not restore the old fresh-procfs gate, host discovery, Console manager, or target signal wrapper. Keep the acceptance-time integrity distinction between environment and descriptor configuration.
4. Carry forward the executable tests and deterministic fixtures with the implementation. Follow the validation checklist below, recording actual revisions, artifacts, host capabilities, skips, and failures. Recheck both ordinary native entry points and the runner's hooks. Test-observer requirements must not become production prerequisites.
5. Regenerate Cargo lock state against the new workspace. If Rust dependencies change, run `just bazel-lock-update` from the repository root and review `MODULE.bazel.lock` with `Cargo.lock`. Inspect the complete new upstream diff for accidental enforcement or dependency changes; update the base revision and inventory from that diff. Verify documentation links, paths, symbols, and test selectors, then format changed Markdown with `yamark format --wrap paragraph` and run `git diff --check`.
6. Commit and push new commits without amending or force-pushing. Report local and hosted validation separately. Downstream adoption is a separate task: select an exact tested revision and rebuild its artifacts; an old handoff pin is not an instruction to downgrade.

## Validation checklist

The executable commands and job definitions live in [.github/workflows/mcp-console-sandbox.yml](../../.github/workflows/mcp-console-sandbox.yml); use its current commands rather than copying a historical transcript. [README.md](README.md#build-and-validation) describes builds, artifact staging, and Cargo target-directory resolution. [LINUX_COMPATIBILITY.md](LINUX_COMPATIBILITY.md) distinguishes native host capabilities from test-fixture prerequisites.

- On macOS and GNU Linux, run the complete executable suite with `just test --locked -p codex-mcp-console-sandbox --retries 0` against debug and release runners. On Linux, build ordinary bubblewrap first and set `CARGO_BIN_EXE_bwrap` to the matching artifact. For release contracts also set `CARGO_BIN_EXE_mcp-console-sandbox`. Keep interposer tests on dynamically linked executables.
- Run `just test -p codex-sandboxing` on macOS and `just test -p codex-sandboxing -p codex-linux-sandbox -p codex-bwrap --retries 0` on Linux. The workflow adds the built debug helper to PATH only for native Linux tests because an existing fallback fixture copies it. Review the macOS exclusions below against the new release.
- Run `bazel test //codex-rs/mcp-console-sandbox:bootstrap-contract-test` on both platforms. A host-policy or dependency-download failure is a validation limitation, not a passing runtime gate. Record any test-only AppArmor accommodation separately from ordinary-helper results; do not change enforcement to obtain a pass.
- Preserve the workflow's x86_64 and aarch64 musl builds, helper strip/hash order, build-scoped toolchain variables, ELF dependency checks, and static-artifact `transport::` / `lifecycle::` contracts. These checks complement GNU fault-injection coverage. They do not establish portability of a target's own runtime or libraries.
- Review the [procfs differential tests](LINUX_COMPATIBILITY.md#procfs-evidence) on a host that can exercise real fresh and inherited views. The runner's injected identity test alone does not establish their visibility/policy contract. Keep downstream integration results tied to the tested downstream and runner revisions.
- Run scoped Clippy and `just argument-comment-lint -p codex-mcp-console-sandbox`. For implementation changes, run `just fix -p` for the changed packages and `just fmt` from `codex-rs` after functional tests; do not rerun tests solely because fix/format ran. Follow the repository's approval rule before any full-workspace suite.

The workflow currently excludes `create_seatbelt_args_with_read_only_git_and_codex_subpaths` and `create_seatbelt_args_with_read_only_git_pointer_file` from the macOS native suite. Both were reproduced at the pinned upstream base: the operation was denied, but the stderr matcher rejected Bash's `line 1:` prefix. These are existing host-specific assertion failures, not policy exemptions. Reconsider the exclusions on each upgrade; all runner contracts still run.
